# Fixed-income source records

Issue #13 adds source records and a read-only UI, not valuation. Apply Alembic revision `0021` before using the endpoints. Fixed-income lots do not enter the equity transaction ledger or the current valuation engine.

The instrument catalog loader also seeds provider-free CDB, LCI, and LCA identities from `data/fixed_income_products.csv` into `fixed_income_products`, which stores default currency and contractual conventions. Run `python -m src.instrument_catalog` after updating. `GET /api/fixed-income/products` supplies the form. The form pre-fills advanced fields; the lot creation endpoint fills omitted fields from the product template and stores the resolved values on the lot, so later catalog updates do not change existing contracts. Product terms, issuer, broker and application currency belong to each lot. Recorded lots appear under Positions, and their source movements appear under Transactions, with valuation and return pending.

Select a canonical product or create a portfolio-private fixed-income instrument with `POST /api/portfolios/{portfolio_id}/fixed-income/instruments/custom`. Create a lot with `POST /api/portfolios/{portfolio_id}/fixed-income/lots`; read it with the matching list and detail GET endpoints. A lot is tied to a portfolio asset, but its dates, terms, issuer, broker and currency are independent. Creation requires `opening_amount` and atomically records an `INITIAL_INVESTMENT` movement dated on `start_date`. Further monetary movements use `POST /api/portfolios/{portfolio_id}/fixed-income/lots/{lot_id}/movements` and the matching GET endpoint. Movements must use the lot currency. Source movements cannot be edited through the API; corrections require a later explicit reversal workflow.

`fixed_rate` and `benchmark_spread` are annual decimal fractions: `0.12` means 12% per year, and `0.06` means six percentage points per year. `benchmark_multiplier` is a pure multiplier: `1.10` means 110% of the selected benchmark. These fields have distinct meanings and are mutually exclusive according to `yield_structure`. API responses encode monetary amounts and contract decimals as strings to preserve precision. Benchmark-linked lots require an active canonical `benchmark_id`; the fixed-income service neither creates benchmark identities nor fetches observations. Benchmark currency does not set lot currency.

Every lot explicitly records `day_count_basis` (`BUS_252`, `ACT_365`, or `ACT_360`), `compounding` (`SIMPLE` or `COMPOUND`), `business_day_calendar` (`BR` or `NONE`), and `benchmark_lag_months` (0–24). These are preserved contract inputs; no accrual is performed yet. Additional calendars and product codes can be supported without changing the tables.

All lot responses report `current_value: null` and `valuation_status: pending`. Portfolio overview exposes pending fixed-income lots and sets aggregate `total_value` to `null`; consolidation reports incomplete while any such lot exists. Portfolio history retains earlier dates, but reports null aggregate values and returns from the earliest lot start date. Individual equity position history remains available. Principal is never substituted for current value.
